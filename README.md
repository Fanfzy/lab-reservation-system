**实验室预约管理系统**

基于Python、Django和SQLite的实验室预约管理软件，提供申请人和管理员两类角色。系统完成资源查询、预约申请、管理员审核、开始前取消、记录查询和统计，并在保存前判断时间冲突。仓库同时提供需求分析、设计模型、测试和使用文档。

**主要功能**

| 功能 | 使用方式与结果 |
|---|---|
| 登录与账号管理 | 申请人登录使用；管理员创建、修改和启停账号 |
| 实验室管理 | 管理员维护编码、位置、设备、容量、开放时间及可用状态 |
| 资源与占用查询 | 按关键词、最低容量、状态筛选，按日期查看占用 |
| 预约申请与冲突判断 | 提交未来时段、人数和用途，成功后生成待审核记录 |
| 预约审核 | 管理员批准或填写理由拒绝，保存审核人、时间和决定 |
| 预约记录与取消 | 申请人查看本人记录，管理员查看全量；开始前确认取消 |
| 基本统计 | 按预约开始日期汇总数量、状态、资源和获批计划时长 |
| 操作追踪 | 保留申请、审核、取消、资源及账号维护的关键操作 |

**运行环境**

已验证环境为Windows、Python 3.12.15、Django 5.2.17、SQLite 3.53.4。使用Conda管理独立环境，建议路径为 `D:\conda_envs\lab_booking`。SQLite随Python环境提供，浏览器直接解释HTML、CSS和少量JavaScript。

`environment.yml`声明Python、Django和libsqlite三个直接依赖，`conda-win-64.lock.txt`记录Windows 64位环境的精确包集合。现有24个环境包均能追溯至这些直接依赖。

**首次运行**

下载或克隆本仓库，打开仓库根目录，即包含 `manage.py` 的目录。在PowerShell中运行下面命令。已有同一项目环境时，可以直接进行建库和初始化。

```powershell
conda env create --prefix D:\conda_envs\lab_booking --file environment.yml # 首次使用时创建独立环境，安装前确认目标位置。
& 'D:\conda_envs\lab_booking\python.exe' -B manage.py migrate --noinput # 建立或更新数据库表结构。
& 'D:\conda_envs\lab_booking\python.exe' -B manage.py seed_demo # 创建缺失的演示账号、资源和预约样本。
& 'D:\conda_envs\lab_booking\python.exe' -B manage.py runserver 127.0.0.1:8000 --noreload --insecure # 启动本机服务并提供本地静态资源。
```

浏览器访问 <http://127.0.0.1:8000/>。保持服务窗口运行，停止时在该窗口按Ctrl+C。

Windows也可在环境准备后双击 `初始化演示数据.cmd`，再双击 `启动系统.cmd`。日常使用只需启动系统。三个CMD入口使用现有解释器，环境位置变化时可先设置 `LAB_BOOKING_PYTHON`，端口变化时设置 `LAB_BOOKING_PORT`。

`System check identified no issues`表示检查通过，`No migrations to apply`表示数据库结构已更新。启动窗口中的开发服务器提示说明当前采用本机演示运行方式。看到 `Starting development server` 后即可访问页面。

**核心规则与演示流程**

整间实验室独占预约。待审核和已批准都占用时段，已拒绝和已取消释放时段。相邻时段允许衔接，例如11:00—12:00与12:00—13:00可以同时成立，11:00—12:00与11:30—12:30存在冲突。

预约须在未来同一天、实验室开放时间内，精确到分钟；人数须为正整数且不超过容量。管理员审核，拒绝时理由必填。申请人可在开始前确认取消本人有效预约，管理员也可在开始前取消。取消后保留原申请、审核和操作经过。

建议依次演示：user01查询资源并申请未来11:00—12:00，user02申请交叠时段观察冲突提示，admin01批准第一笔，user01查看结果并确认取消，最后核对时段释放及统计变化。统计中的获批时长表示预约计划时长。

**测试与维护**

在仓库根目录执行：

```powershell
& 'D:\conda_envs\lab_booking\python.exe' -B scripts\check_sources.py # 核对自有源码语法和逐行注释约定。
& 'D:\conda_envs\lab_booking\python.exe' -B manage.py check # 核对框架配置。
& 'D:\conda_envs\lab_booking\python.exe' -B manage.py makemigrations --check --dry-run # 确认数据模型和迁移一致。
& 'D:\conda_envs\lab_booking\python.exe' -B manage.py test tests --noinput -v 2 # 在独立测试库中执行31项测试。
```

Windows可直接双击 `测试系统.cmd`。测试覆盖交叠与相邻边界、容量、审批与取消、归属权限、CSRF、事务回滚、两个独立连接的并发提交、重复初始化、备份和启动入口。每个测试方法可能包含多组输入。

日常数据位于 `runtime/db.sqlite3`，日志位于 `runtime/system.log`。`database/demo.sqlite3`是初始演示快照，日常数据库通过迁移和初始化命令准备。备份、恢复与环境变量详见[运行维护说明](04_运行与交付/运行维护说明.md)，演示步骤详见[现场演示脚本](04_运行与交付/现场演示脚本.md)。
