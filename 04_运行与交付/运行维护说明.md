**本机启动与数据位置**

先把系统理解为三个部分：Conda环境提供运行工具，项目文件规定怎样处理预约，数据库保存你在页面上填写的实际资料。浏览器是操作入口；关闭浏览器不会把后台服务或数据库删除。

| 名词 | 实际含义 | 使用时怎样判断 |
|---|---|---|
| 解释器 | 执行Python程序的工具 | 本项目使用专用环境中的python.exe |
| 端口 | 本机服务的入口号码 | 地址中的8000应与启动配置一致 |
| 迁移 / migrate | 按项目步骤建立或更新数据表 | “No migrations to apply”表示结构已更新 |
| 会话 | 系统记住浏览器当前登录身份 | 退出后需要重新登录，不能靠改网址获得权限 |
| 演示快照 | 交付时准备的数据库样本 | database中的文件不会跟随当前页面变化 |
| 备份 | 业务数据的一份一致副本 | 恢复会用备份内容替换当前数据，先确认文件 |
| 日志 | 程序异常的诊断文字 | 不是预约台账，也不代替数据库备份 |

详细业务规则和图示读法见[模型说明与读图指南](../02_系统设计/模型图/模型说明.md)。第一次演示可以先申请相邻时段，再尝试重叠，最后用管理员批准并取消，以观察占用和统计怎样变化。

默认专用环境为D:\conda_envs\lab_booking。项目根目录指包含manage.py和README.md的下载或克隆目录，具体位置由使用者选择。双击启动系统.cmd，保持窗口打开，访问http://127.0.0.1:8000/。该脚本检查解释器、核对1至65535的端口及占用、执行迁移、启动本机服务，不安装任何依赖。初始化演示数据.cmd只补齐缺失演示项。测试系统.cmd运行独立测试库，不修改正常业务数据库。

“System check identified no issues”是检查通过；“This is a development server”说明本机课程演示模式，不是报错。启动失败会保留窗口；正常停止在服务器窗口按Ctrl+C。管理员修改本人密码后当前会话保持有效。取消的POST请求必须包含confirm_cancel=yes，页面确认框会自动发送；未确认不会取消。

CMD控制文本采用ASCII与CRLF换行，中文提示由check_local_port.py输出；Python结果仍使用UTF-8。修改入口时不直接加入中文rem/echo语句。启动前显示的地址是操作说明，看到“Starting development server”才表示已经监听；“No migrations to apply”说明表结构已更新，无需重复迁移。

运行数据保存在runtime/db.sqlite3，异常日志为runtime/system.log及最多三个轮转文件。database/demo.sqlite3是初始演示快照，不会随页面操作更新。测试库runtime/test-suite.sqlite3仅用于验证，不是业务数据。环境、代码、运行数据的存放位置有意分开，搬运项目不等于已搬运Conda环境。

**环境变量配置**

| 进程变量 | 默认/用途 |
|---|---|
| LAB_BOOKING_PYTHON | 三个CMD脚本默认D:\conda_envs\lab_booking\python.exe；换设备可指定解释器 |
| LAB_BOOKING_PORT | 启动系统.cmd默认8000 |
| LAB_BOOKING_DB | 未设置时runtime/db.sqlite3；独立验证使用其他文件 |
| LAB_BOOKING_DEBUG | 默认0；开发时1打开详细调试 |
| LAB_BOOKING_SECRET | 本地课程演示默认值；公开运行应设置独立秘密值 |

修改环境变量仅影响该进程，重启后生效；浏览器关闭并不会停止服务器。不要在已运行进程中期待配置自动热更新。静态资源本地提供，启动参数--insecure允许DEBUG关闭时的本机开发服务器提供静态文件。

**日常操作**

申请人：登录→实验室查询→详情选日看占用→预约→填写未来同日区间、人数和用途→提交→我的预约查看。管理员：账号/实验室维护→预约审核列表→打开详情→批准或填写理由拒绝→查看全量记录、统计和操作记录。取消时勾选页面确认，开始前提交。资源或申请内容变化以后，旧页面可能过时，服务会重新检查并提示刷新。

新建演示样本使用初始化当天的次日，已有样本不会自动改日期。后续演示请创建新的未来预约，不应为了让旧样本“看起来新”而改历史时间。日期统计默认本月，筛选口径是预约开始日，当前状态改变后统计也随之改变。

**数据库备份和恢复**

备份脚本使用SQLite.backup产生一致文件，目标必须不存在。建议在修改数据库结构或恢复前先备份。以下命令从项目根目录执行，具体文件名按实际日期/版本调整：

```powershell
# 对当前业务数据库创建一个新的备份文件。
& 'D:\conda_envs\lab_booking\python.exe' -B scripts\backup_database.py runtime\db.sqlite3 backups\预约数据_独立快照.sqlite3
```

恢复步骤：停止服务器→确认目标绝对路径是本项目runtime/db.sqlite3→备份当前文件到新名称→验证恢复候选的integrity_check=ok和版本/账号/记录→把候选复制到runtime/db.sqlite3→运行migrate→启动并登录核对。恢复属于覆盖当前业务数据的动作，使用者执行前必须确认所选备份；本文不提供自动覆盖现有数据的按钮。

独立目录验证可按README依次执行migrate、seed_demo和31项测试。TC-020验证重复初始化保留已有数据，TC-023验证备份完整性及内容一致；备份工具为scripts/backup_database.py。database/schema.sql提供空结构参考，标准建库与升级入口为manage.py migrate。

**常见问题**

| 现象 | 检查与处理 |
|---|---|
| 找不到Python | 核对Conda环境位置或LAB_BOOKING_PYTHON，不要临时换成系统Python |
| 找不到Django | 确认该解释器和环境清单；安装需要先确认环境，不运行脚本自动安装 |
| 8000端口占用 | 已有服务可直接使用；否则选择新端口并修改浏览器地址 |
| 页面没有样式 | 使用启动脚本或带--insecure的本机启动方式，检查本地static路径 |
| 密码不对 | 初始密码只适用未被修改的新演示账号；初始化不会重置密码 |
| 时间冲突 | 查看同资源日期的待审/批准占用，选择相邻或其他时段 |
| 数据库忙 | 短时间后重试；若持续检查是否有其他工具占用写事务 |
| 停用/调整资源失败 | 处理尚未结束且不兼容的占用，或保留原容量/开放时间 |
| 不能再批准或取消 | 已开始、终态或已被他人操作，刷新看最新状态 |
| 500错误 | 查看runtime/system.log，核对诊断与实际发生时间，再定位相关请求 |

**环境复现和卸载边界**

environment.yml记录本项目直接依赖，Windows平台锁文件记录实际解析结果。换设备需要Conda可用、网络可取得锁文件中的包，并按说明初始化；本次已验证同环境下搬运到新目录，未在另一台电脑重新联网安装。

停止服务后可以移走项目副本；需要清理环境时只删除或移除D:\conda_envs\lab_booking这一专用环境，先确认没有其他项目使用它。Conda共享缓存和现有Conda安装属于环境管理器，不通过项目脚本删除。本次未安装Node、数据库服务、全局Python包或浏览器扩展。
